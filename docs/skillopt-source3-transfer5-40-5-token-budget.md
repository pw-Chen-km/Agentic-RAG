# 40 題產生紀錄，最多 5 題一組分析；太長時拆成更小組

這是另外一個明確開啟的新設定，不會修改先前固定 40 / 5 的設定或結果。
建立設定時，同時指定：

```shell
--design single_source_cross_dataset_v1 \
--reflection-minibatch-size 5 \
--reflection-token-budget-enabled
```

必須使用新的輸出資料夾。沒有最後一個開關時，維持先前的分組方式。
建立設定本身不連線、不呼叫模型，也不會開始訓練。

## 哪裡改變，哪裡不變

Agent 仍用同一份 Skill 完成最多 40 題。分析仍先依原本的方法，把成功與失敗紀錄分組，每組最多 5 題。
新的差別只有：送出分析前，先計算整份請求的長度；如果放不下，就把這一組拆小。

例如，5 題加上分析指令太長，可以改成兩組較短的完整紀錄；不是刪掉某幾題，也不是把每題的內容截短。
所有組別都分析完，才進行原本的建議合併、篩選與驗證。這批 40 題仍最多更新一次 Skill，不會因為拆組就多更新。
Medical 最後 12 題及 Novel 最後 2 題也照常保留。

四種紀錄表示方式都使用相同的限制：

| 項目 | 固定值 |
|---|---:|
| 一批 Agent 題數 | 最多 40 |
| 一次分析的紀錄數 | 最多 5 |
| 模型整體容量 | 262,144 tokens |
| 預留模型回覆空間 | 16,384 tokens |
| 額外保留空間 | 1,024 tokens |
| 可用的輸入上限 | 244,736 tokens |

這裡計算的是模型使用的 tokens，不是中文字數或檔案大小。計算包含分析時真正送出的完整指令、Skill、問題與紀錄。
如果單獨一題仍放不下，必須停止並留下原因，不可悄悄刪除內容、縮減回覆空間或擴大模型容量。

## 設定如何固定

每條執行路徑的 YAML 都記錄相同的容量與預留空間，並記錄該路徑的 AMD port，讓計算長度時使用對應模型。
SSH 設定只保存連線位置與金鑰檔案路徑，不會把金鑰內容放進設定或送給 LLM。

總設定記錄 `reflection_grouping: adaptive` 與 `reflection_token_budget`，包含上述全部限制。
容量檢查也必須使用這份新設定；不能拿舊的固定 5 題容量證明直接套用。
舊設定不會自動被新功能接管，也不允許覆蓋舊實驗資料夾。

## 解讀結果時要注意

拆小後可能需要更多次分析，重複讀取共同指令，因此不保證總花費更低。
原始紀錄通常比整理後的紀錄長，四組實際拆出的組數可能不同。比較時應保存每次真正包含哪些題目、輸入長度與呼叫成本，不能宣稱四組分析次數完全相同。

其餘設置不變：三個資料集各訓練四種表示方式，12 組全部完成後才進行 65 組最終測試；資料、Skill 起點、模型、索引、提示內容與驗證方式維持既定設定。
